# 約90秒の動作確認

この手順はローカル実行用です。公開デモのURLや共有管理者アカウントはありません。画面例のGIFは既存スクリーンショットの切り替えであり、操作を録画した動画ではありません。

## 準備

READMEのDocker手順で、実データを含まないデモ用DBを起動します。初期管理者でログインし、部署、社員、LOCALのUSERアカウントを登録してください。メールには`example.com`、社員名には架空の名前を使用します。パスワードは手元だけで管理します。

| 目安 | 操作 | 見せたい点 |
| --- | --- | --- |
| 0〜15秒 | ADMINでログインし、ダッシュボードから社員一覧へ移動 | MVC画面とセッション認証 |
| 15〜30秒 | 社員名の先頭を入力して検索 | 前方一致検索、ページング |
| 30〜50秒 | 社員の編集で退職状態を選択し、退職日を空にして保存。その後、正しい退職日で保存 | 入力チェックと業務ルール |
| 50〜65秒 | 更新した情報が一覧に反映されたことを確認 | 永続化とAPIを使った画面更新 |
| 65〜90秒 | ログアウトしUSERでログイン。社員を閲覧し、更新ボタンやユーザー管理が使えないことを確認 | 権限ごとの画面。API側の拒否はCIのテストで確認 |

Googleログインはこのデモに必須ではありません。実Google接続の確認は[OAuth検証手順](oauth-verification.md)に分けています。

## 面接で説明する順番

1. 社員・部署・ログインアカウントを管理する用途を説明する。
2. サーバー側で認可・入力検証・データ整合性を担保した箇所を示す。
3. レビュー前の問題を一つ選び、修正理由と回帰テストを説明する。
4. 実装済み、検証済み、まだ確認していない事項を区別する。
