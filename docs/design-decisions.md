# 設計方針

## 認証と権限

管理画面とREST APIはセッション認証を共有するため、両方でCSRFを検証します。社員・部署の更新とアカウント管理はADMIN権限に限定しています。

Googleログインは管理者が事前登録したGOOGLEアカウントだけを許可します。検証済みメールを確認し、初回ログイン時にsubjectを固定します。LOCALアカウントとは別に管理します。

## DTOとAPI互換性

フォームDTOはSpring MVCのバインディングに合わせた可変クラス、共通のApiResponseはrecordです。Entityを入力として直接受け取らず、DTOの検証を通して更新します。

APIは既存クライアントとの互換性を保つため、`status/message/data` 形式を使用します。HTTPステータスで未認証、権限不足、入力不正、未検出、重複を区別します。Problem Detailsへの移行はクライアントの変更と合わせて検討します。

現在の規模ではcontroller・service・repositoryのレイヤー別構成を使用しています。機能間の依存が増えた段階で、機能単位への分割を検討します。

## データ管理

スキーマ変更はFlywayで管理し、起動時はJPAで検証します。既存データベースを使う場合は [移行手順](database-migration.md) を確認してください。

社員の削除は論理削除です。検索・詳細・集計から除外しますが、メールの一意制約は保持します。作成者・更新者と日時は更新の追跡用メタデータで、変更内容を時系列に保存する監査台帳とは異なります。

## 検証と今後の拡張

GitHub ActionsでJava 17のMaven `verify` とNodeの回帰テストを実行します。Javaテスト27件、Nodeテスト3件で認可、CSRF、OIDC、パスワード、API、テンプレート、論理削除を検証しています。H2とMySQL 8.0.45での移行・起動、ブラウザでのログイン・検索・編集フォーム表示も確認しています。

実際のGoogle OAuth設定とDocker起動は未検証です。公開デモ、組織階層、CSV入出力は今後の拡張候補です。公開ライセンスは未設定です。
